# M1.5 checklist: multi-campaign

## Start it

1. Make sure Docker Desktop is running. If `mise run dev` is running, press Control-C in its tab. The server has to restart to pick up M1.5.
2. **The next command erases your local data.** M1.5 starts from a new database. Your current one was built by earlier migrations, so `mise run dev` and `mise run seed` refuse it and say to run `mise run fresh`, which rebuilds it and loads the two sample campaigns:

   ```bash
   cd ~/myCodeSpace/colony-planner
   mise install
   mise run fresh
   mise run dev
   ```

   Wait for `dev: open http://localhost:5173`. The first start after an update can stop while Vite re-bundles the web code. If the page doesn't load, press Control-C and run `mise run dev` once more.
3. Leave `DISCORD_GUILD_ID` in `.env` for now: Beny Bot uses it once to clear its old commands (Try it, step 17).

The steps build on each other, so do them in order. A private window counts as a second person; a second browser (Safari next to Chrome) is a third. Pages outside a campaign (the list, Site admin, the request page) update when you click into their window.

## Try it

1. **Sign-in page.** The Dev sign-in list shows each person once with their roles: "Sample DM · site owner · DM of Sample Colony", "Ana · Thorin in Sample Colony · Brisa in Second Sample", "Hollis · DM of Second Sample · Pell in Sample Colony", "Wren · asking to run a campaign".
2. **Your campaign is unchanged.** Sign in as **Sample DM**. You land on your campaign list; open Sample Colony (`/c/sample-colony/`): Port Eldari, Day 22, Food 63, as in the M1 checklist. Next time, the list takes you straight to the campaign you opened last.
3. **One person, two campaigns.** In a private window, sign in as **Ana**. The page lists Sample Colony (Thorin) and Second Sample (Brisa). Open Second Sample: Ridgehold, Day 9, Food 140, a Timber tile, and her name is Brisa. Use the colony name in the top bar (Ridgehold) to open the switcher, which lists her campaigns, and switch to Sample Colony: Port Eldari, Thorin.
4. **Campaigns don't hear each other.** Put Ana on Second Sample. In your window, tap **+3** and advance. Ana's window shows no toast and stays on Day 9. Switch Ana to Sample Colony: Day 25.
5. **You run the site, not their game.** In your window open the profile menu → **Site admin**.
   - Campaigns lists Sample Colony (you) and Second Sample (Hollis, @hollis.sample) with player and waiting counts and "Discord: not linked". No day, stock or timeline appears.
   - Type `localhost:5173/c/second-sample` in the address bar: "No such campaign".
   - Back on Site admin, Second Sample's ⋮ menu → **Copy ID**. Open `localhost:5173/api/campaigns/<paste>/colony`: the browser shows a small JSON error, status 404, "No such campaign." The server itself refuses you, not just the page.
6. **Saying no to a campaign.** Requests shows Wren's "Sample Sky Isles" with her note. Tap **Deny**. In a private window sign in as **Wren**: she sees "The site owner said no this time" and **Run your own campaign** is offered again. Leave it.
7. **A friend starts a campaign.** In Safari, Dev sign-in → "A new person" → **Mira**. She lands on an empty list with **Run your own campaign**. She asks for "Sky Isles" with a note. She sees "Waiting for the site owner", with **Withdraw** and no way to send a second request.
   - Click into your window: Site admin shows the request. Tap **Approve**.
   - Click into Mira's window: "Sky Isles is ready". **Open it**: The Colony, Day 0, Gold, Food, Materials and Morale, the Unassigned row (roles show once colonists are assigned), the DM tools, and a hint pointing to Settings. In **Settings** she names the colony "Gullhaven" and picks her timezone; the board shows Gullhaven.
8. **Invite link.** As Mira, **Settings** → **Invite link** → **Copy**.
   - In a private window in Chrome, sign in as a new person **Nico** and paste the link. "Join Sky Isles, run by Mira?" → **Ask to join** → "Waiting for Mira".
   - Mira's **Players** shows Nico without a refresh. **Let in**: Nico's window opens Gullhaven by itself.
   - Mira taps **Reset link…**. Opening the old link now says "This invite link doesn't work any more".
9. **Removal is per campaign.** In a private window sign in as **Hollis** → Second Sample → Players → remove **Ana (Brisa)**. Ana's Second Sample window shows "You don't have access" at once, and her Sample Colony tab keeps working without signing in again.
   - Hollis copies Second Sample's invite link; Ana opens it: "You don't have access to Second Sample", no **Ask to join** button. Hollis's Players shows no new waiting person, and Ana is listed as **Removed**.
   - Hollis re-admits her.
10. **A DM elsewhere is a player here.** As Hollis, switch to Sample Colony. He's Pell, a player: no +/− buttons, no Players management, no Invite link or Discord cards in Settings, and the Timeline has no "Paid the smuggler at the north cove" entry.
11. **Leaving a campaign.** In a private window sign in as **Iko** (Tamsin Vale in Second Sample). Profile menu → **Leave this campaign…** → confirm. She lands on her campaign list, where Second Sample says No access.
    - Hollis's Players shows Iko as **Left** (Ana, removed by Hollis in step 9, said **Removed**).
    - Iko opens Second Sample's invite link (Hollis copied it in step 9): "You don't have access to Second Sample", no **Ask to join** button, and Hollis's Players shows no new waiting person.
    - Only Hollis can bring her back: he taps **Re-admit** on Players.
    - As Hollis, open the profile menu inside Second Sample: there is no **Leave** entry for the DM.
    - Sign in as **Jun** (waiting to join Second Sample): the waiting page has **Stop waiting**. Tap it: Jun is listed as Left on Hollis's Players.
12. **View as player.** In your Sample Colony turn on **View as player**. Open Site admin: it still works. Go back: the banner is still on. Turn it off.
13. **Pausing a campaign.** On Site admin, **Suspend** Second Sample. Hollis's Second Sample window shows "This campaign is paused by the site owner" at once; Ana's Sample Colony is untouched.
    - In a private window, a new person **Quinn** opens Second Sample's invite link: "Second Sample is paused by the site owner", no **Ask to join** button.
    - **Unsuspend**: Hollis's window works again without a reload.
14. **The owner deletes a campaign.** On Site admin, Sky Isles' ⋮ menu has no **Delete…** while it is active. **Suspend** it. **Delete…** lists what will go. Type `sky-isles` and confirm. It disappears from Site admin; Mira and Nico still sign in and see an empty list. Open Sky Isles' current invite link: "This invite link doesn't work any more".
15. **A DM deletes their own campaign.** As Mira, **Run your own campaign** again ("Sky Isles Two", address `sky-isles-two`); approve it on Site admin. Mira opens it → **Settings** → **Danger zone** → **Delete this campaign…**. Typing anything but `sky-isles-two` keeps the button disabled. Type `sky-isles-two` and confirm: Mira lands on her empty campaign list, and Site admin no longer lists it. Sample Colony and Second Sample are unchanged. (Players see no Danger zone: Settings is the DM's.)
16. **Database view (optional).** `mise run db:studio` → http://localhost:54330. The `campaign` table has two rows, and `colony`, `resource`, `role`, `timeline_event` each have a `campaign_id` column.
17. **(Discord) Link your server.** With Beny Bot Dev set up (`docs/discord-dev-setup.md`, updated; "Coming from M1" says what changed): the first start logs `old guild commands cleared; delete DISCORD_GUILD_ID from .env`. Press Control-C, delete the `DISCORD_GUILD_ID` line from `.env`, and run `mise run dev` again. Allow a minute for commands to appear.
    - In Sample Colony **Settings → Discord server**, tap **Get a link code**. In your test server run `/link code:BENY-...`. Settings shows "Linked to <your server>". Pick your DM channel from the list.
    - In Safari, a new person opens Sample Colony's invite link and asks: Beny Bot posts in that channel.
    - `/beny` answers "Boy!". Running `/beny` as a Discord account that isn't in Sample Colony says "You're not in this campaign".
    - A server member without Manage Server doesn't see `/link` (or is refused if your server shows it).
    - Get a code in Second Sample (as Hollis) and run `/link` with it in the same server: refused, "already linked". An expired or mistyped code is refused.
    - **Unlink…** in Settings: `/beny` now says the server isn't linked.
18. **(Discord) Removing the bot unlinks.** Link the server again. Press Control-C in the `mise run dev` tab, remove Beny Bot Dev from your server in Discord, run `mise run dev` again: Settings shows "Not linked".
19. **(Discord) A request pings you.** With Beny Bot Dev on (and invited back), a new person asks to run a campaign: Beny Bot sends you a direct message linking to Site admin.
20. **Checks.** In a second Terminal tab run `mise run check`. It ends with "All checks passed" after a few minutes. It includes the cross-campaign secrecy sweep (players who DM elsewhere, outsiders, the owner, the DM with the other campaign's IDs in paths and bodies, a suspended campaign, deleting and leaving; the other campaign's rows must stay unchanged), the SQL scope check, the migration tests, and the idle-tab and reconnect tests.

## When you're done

- Press Control-C in the `mise run dev` tab. `mise run db:down` stops Postgres; your data is kept.
